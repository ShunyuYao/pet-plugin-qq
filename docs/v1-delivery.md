# 0.1.0 首版记录 · 2026-11-01

## 已确认要求

QQ 与桌面是同一只宠物，聊天能互相接着聊；必须支持已有 QQ 宠物；B 站生活联动可选、不强制。用户授权新建 GitHub 项目实现并测试，首个后端由实施方选择。仓库默认私有，未执行公开发布。

## 实施选择

首个目标为 NapCat OneBot v11 + 已有 DSH 0.2.1-rc.2 Session。自写业务桥接，复用 NapCat 登录及 QQ 协议；没有复制第三方 qq-bridge 的实现。原第三方桥接的自动发送与独立状态不能直接视为兼容，接管前须停用旧收发、在 DSH 确认角色与记忆。

桌面走宿主新增的 tool-only experimental conversation 接口。插件不访问宿主私有聊天库；DSH 是会话权威。绑定按账号×宠物持久化，凭据及请求账本加密保存。旧 storage 的吞写错误语义不适合可靠消息账本，故账本使用会抛出写失败的 secrets；宿主凭据仓改为原子替换，避免进程中断截断旧账本。

## 验证层次

1. 协议回归：保留接入前历史；双向接续；源端回复；重复消息去重；好友/主人/机器人身份校验；群、临时、陌生人、自身与非文本拒绝；取消、发送未知与重启不重放。
2. 真实 DSH 0.2.1-rc.2 进程：本地 SSE 模型服务收到 4 次真实 DSH 模型请求，后续请求包含旧话题和另一端输入；QQ 协议服务收到 1 次回复。测试使用独立 DSH_HOME 与新建的测试会话，先建立旧历史再让插件接入。
3. 真实 Electron：普通 utilityProcess 插件和 sandbox 面板，连接后原主聊天显示旧历史，双向接续、去重、离线、重连、重启恢复及解绑；无 B 站插件。设置输入和按钮走 CDP 输入通道，保存页面截图及结果。
4. 宿主契约、类型包与脚手架核对：会话归属/作用域、权限、白名单、离线不回落、生成桥一致性、公开类型和文档矩阵。

## 已知边界

尚未验证真实登录 QQ/NapCat、真实远程 DSH 部署、付费模型的语义理解、Windows/Linux、第三方角色/社交状态迁移。B 站跨端联动未启用。没有发布宿主、npm 或市场包。

测试发现并处理：隐藏 E2E 在 React 订阅前直接展开会漏掉状态，改为真实展开按钮；面板状态返回 undefined 字段被 SDK 白名单拒绝，改为明确空字符串；基线的快捷动作签名与统一 SDK 服务夹具滞后，保留原权限意图并按实际当前契约修正。测试证据由各测试脚本写入 gitignored artifacts，不含真实账号凭据。
