## 服务契约（开发入口，尚无群 UI）

调用方式为本插件面板内的 `pet.services.invoke('qq-context', method, args)`。拒绝其他插件、block、宿主聊天等调用方；本批**没有**给主聊天开放群查询工具。

| 方法 | 参数 / 返回 |
| --- | --- |
| `groupConnect` | 一个配置对象，见下方；成功返回 `{connected:true}`，仅允许创建当前作用域的首次配置。 |
| `groupState` | 无参数；连接、错误、记录数、最近区间和去令牌配置。始终明确 `groupReplies:false`、`model:'not-connected'`。 |
| `groupPause` | 无参数；关闭 QQ 连接，保存暂停偏好。持久化失败会报错，不能当成暂停偏好已保存。 |
| `groupResume` | 无参数；按原配置重连。不补齐离线消息，不重放聊天生成。 |
| `groupMessages` | `{groupId,after?:number,limit?:number}`；按接收序号返回 `messages/next/hasMore`。只允许当前配置的群，当前机器人由服务端填入。 |
| `groupMessageDetail` | `{groupId,messageId,offset?:number}`；返回原消息 JSON 的 `content/next/hasMore` 分块及 `availability`。逐块拼接后解析；撤回／过期只返回已移除内容。 |
| `groupClear` | 先暂停，再传 `{confirm:'删除当前测试桌宠的群采集数据'}`；删除当前作用域的群资料和群连接配置，不删除旧私聊数据。不可恢复，真实数据清理前应按需要备份。 |

配置字段：`qqUrl`、可选 `qqToken`、`botQQ`、`groupIds`、`retentionDays`、`maxEvents`、`collectionNoticeConfirmed:true`。**不需要 DSH 地址或 Session ID。**

`retentionDays` 必须由操作者明确选择 1–365 天，容量 1–50000 个消息／撤回占位；不替试点负责人决定默认保留期限。测试中的 7 天、5000 条只用于合成夹具。确认标志表示操作者已在试点群说明采集用途、访问对象及保留期限，不代表程序已经自动发布群公告。

## 数据与可靠性边界

- 配置（含令牌）和群数据写入宿主 `secrets` 的独立 `group.v1.<scope hash>` 键，不使用旧 1000 条聊天账本，不把令牌写入普通 storage 或状态响应。
- 每次事务修改副本，宿主原子写入成功后才更新内存。写入、容量或排队失败均停采并显示错误；未持久化的记录不显示成已保存。
- 本阶段是 **8 MiB 上限的加密单机试点存储**，不是无限群历史数据库。全量快照写入随数据量增大有成本，长期／高流量运行前必须做负载测试并评估分页存储或数据库迁移，不能把小样本通过表述为常开生产容量已验证。
- 原文保留期限按接收时间计算；运行期间每分钟维护，读取时也强制过期。暂停采集仍维护当前作用域；APP 未运行或切到其他身份期间不能执行定时清理，下一次恢复该作用域时先清理。过期和撤回保留来源键／时间等去重墓碑，删除内容和发送者展示信息；墓碑计入容量，避免旧事件重新出现。
- 长原文在列表明确标记截断，但完整消息段可按详情分块读取。附件只保存收到的段和元数据，不下载、OCR 或转写，不编造图片／语音内容。
- 暂停、断线区间被记录；进程中断后，从最后确认时间到恢复时间标为未知，不声称离线期间消息已采集。
- 历史数据格式／作用域不符时拒绝加载，不自动迁移或覆盖。宿主已有凭据读取在损坏／不可解密时可能返回 `null`，本批不能将该行为升级成数据库级损坏恢复保证；真实试点仍需备份与故障验证。
- 仅本机服务地址可用。群资料不进入模型、桌宠私人长期记忆或外部遥测；未新增 Langfuse 依赖，也未上传聊天或测试数据。

## 验证入口

```sh
npm ci
npm run test:group
npm test
PET_PLUGIN_HOST_DIR=/absolute/candidate-host/demo npm run test:e2e
```

`test:group` 保护指定群与身份校验、真实 @、普通文本／非文本／匿名、引用、重复 10 次、撤回先到、写入失败、容量、过期、原文分块、账号切换与暂停恢复。已挂入 `npm test` 的聚合门禁。

真实 Electron E2E 通过生产宿主的 utilityProcess、sandbox 面板与真实 secrets 链路调用群服务，覆盖采集、不向模型或 QQ 发消息、越权拒绝、撤回、暂停、重启后数据与暂停状态恢复、重放去重，并回归旧 DSH 私聊主聊天流程。群服务的 E2E 走真实面板服务边界，**不等于不存在的群界面操作验收**。

验证仅使用合成 QQ／DSH 协议服务。未验证真实 QQ/NapCat 登录收发、真实群、Windows/Linux、长时间满载；未运行真实 DSH 进程测试（本批未修改 DSH 适配）。

2026-11-02 本机执行结果：`npm test` **14/14 通过**（11 个群后端用例、3 个旧协议用例），无跳过；上述宿主的 `react:build` 成功；隐藏真实 Electron E2E 通过。最终集成报告为 `artifacts/electron-1793591546680/report.json`，同目录保留连接与主聊天截图及隐藏窗口记录。截图已人工检查；`groupUI:false` 明确表示本批未交付群 UI。测试进程已退出，没有修改日常 profile 或连接真实 QQ。

## 接下来与待确认

1. M1 界面：群配置、状态、分页原文与暂停／清理入口；PRD 要求实现 UI 前确认布局，目前没有本场景设计定稿。
2. M2 宿主群会话契约：当前 `ai.start` 虽限制工具，却会记录插件经历；现有模型路径不能据此保证排除私人记忆。先明确群专用上下文、允许权限、计费／预算、取消与输出路由，再实现宿主与三仓同步。
3. M3–M4：带来源的候选反馈、人工纠正、独立整理队列与主聊天查询。当前完全未实现，不以真实 @ 解析冒充 @ 回复。

## 本轮发现与防复发

- 发现者／阶段：开发代理在依赖核查时发现本地主检出缺少交接宿主接口；处理：固定远端源码快照作隔离验证，不修改用户脏工作区。防复发：交付记录同时写插件与宿主 SHA，不能只写版本号。
- 发现者／阶段：开发代理在现有 SDK 调用核查中发现后台 AI 会记经历；处理：本批不调用该接口，不先接通群回复再补隐私。防复发：M2 验收必须含群请求中没有私人记忆／跨群数据，工具集合为空。
- 测试先行发现：清理操作主动结束作用域后，统一读后守卫会误判成功删除为身份错误；处理：为明确清理操作保留独立授权事务路径，增加作用域清理断言。
- 测试夹具修正：固定时间的历史合成事件最初被真实时钟判为过期，改为显式注入时钟；防复发：保留期限测试全部使用可控时间，不使用过时历史常量搭配默认实时时钟。

本批未声明反馈识别准确率／召回率；Langfuse 技能只影响本地合成用例的可复核设计，不产生模型质量验收结论。
