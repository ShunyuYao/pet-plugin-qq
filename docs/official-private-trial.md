# 官方 QQ 本人私聊测试（2026-11-05）

用户要求先接私聊、不接群。`0.3.0-dev.3` 新增独立的“QQ 官方私聊”入口，沿用腾讯 SDK 1.0.5 与宿主现有模型。群采集先暂停，原群数据不删除；群发现、群采集与官方私聊互斥，不能同时占用同一机器人。

## 明确边界

- 精确绑定一名主人的 `user_openid`，不是普通 QQ 号。不采用“任何人的第一条消息自动绑定”；其他私聊用户、机器人自身及所有群消息都不能进入私聊模型与回复路径。
- 可在本机复用 Harness 已经扫码绑定的本人白名单，但必须 AppID 一致且白名单唯一。凭据及 OpenID 不写进文档或源码。
- 目前为单轮文字连通性测试：每条文字单独进入宿主 `ai.start(context:'isolated', tools:[], maxSteps:1)`，不读取群内容、桌面私人历史或 Harness 会话，不声称已经同步长期记忆。不下载或理解附件。
- 每日模型调用上限需明确选择（1–500）；实际试点沿用此前的每日 100 次预算。调用串行并至少间隔 6.5 秒，暂停会取消等待与模型任务。次数先预留，失败不自动退款为新调用额度。
- 回复必须携带原私聊消息 ID，目标只能是绑定的本人；保守使用五分钟时效和固定回复序号。发送失败不转主动推送，未知发送结果不重发。

## 本机数据

配置、调用次数、消息 ID 的 SHA-256 去重键及处理状态通过宿主 secrets 加密仓保存。聊天输入、模型回复、附件、用户昵称不写入该账本。去重账本最多 2000 条，不静默淘汰以免旧消息重放；满额后显示错误，须暂停后由维护者处理。切换账号或宠物、解绑／退出和暂停均阻止旧任务继续发送。

暂停后可以在私聊页更新密钥与模型预算，不改变绑定的机器人或主人、不清除去重账本。进程重启将未完成项标为结果未知，不自动补发；暂停状态持久化。

## 实现与验证

- `official-bot.cjs` 仅在显式配置本人 OpenID 时转交 C2C 正文；增加严格原私聊路由的单次发送。
- `official-private.cjs` 管理作用域、本人白名单、隔离单轮模型、预算和投递账本；`group-service.cjs` 通过原有服务公开受面板身份保护的方法并控制群／私聊互斥。
- `panel/direct.js` 与“QQ 官方私聊”页展示收件、回复、预算与任务状态，密钥不回显。
- `test:private` 验证白名单、去重、未知投递、暂停／作用域变化、预算、存储失败及错误脱敏。
- `test:private:e2e` 使用真实隐藏 Electron、腾讯 SDK 和宿主模型调用链，QQ／短信／模型网络为本地合成夹具。验证本人私聊实际发出一次原路被动回复、陌生人与群消息不调用模型、无工具、面板状态、暂停与重启去重。不能把该证据当成真实 QQ 收发验收。
- 本轮按 Langfuse 技能的最小可测原则区分收件、模型、投递与状态，不新增 Langfuse 服务、外部追踪或聊天数据上传。

## 实际试点顺序

确认 Harness 的 QQ 插件已关闭 → 暂停本插件群采集 → 在本机核对并绑定唯一本人 OpenID → 设置预算并确认单轮模型边界 → 连接本人私聊 → 由本人发送一条新文字，核对收件与“已回复”计数及 QQ 实际回复。收到 READY 只算连接建立，不代表完成收发验收。

## 本批结果（2026-11-06）

- `npm test` 为 37 项通过；新增私聊和相邻官方群、旧群反馈、旧 DSH 私聊的隐藏真实 Electron 回归均通过。测试报告与截图只保存在本机忽略目录，不包含在 Git 提交中。
- 用户已确认本人真实 QQ 私聊可用；实际状态中两条本人消息均标为已完成回复，没有把正文保存到私聊账本。
- 随后用户要求切到一个仅有本人和机器人的两人群测试。私聊配置与去重账本保留并暂停，群模式验证完成后可按界面控制切回，不同时运行两个入口。
- 这仍是单轮私聊连通性测试，不等于桌宠长期记忆、原 Harness 历史或完整主人私聊接续已经交付。
