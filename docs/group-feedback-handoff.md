# QQ 群反馈机器人：交接与实施顺序

更新：2026-11-02。拟接手人：黄煜斯。状态：**群反馈首版已实现本地开发候选，真实 QQ 试点待验收**。包含采集、界面、隔离模型、@ 回复、带来源的反馈与人工处理、主聊天查询和重启恢复。见 [使用说明](group-feedback-quickstart.md) 与 [本批记录](group-feedback-v1.md)；原 M1 后端记录保留作历史。

## 要交付什么

在一台专用电脑上保持吐梨邦 APP 和 QQ 接入在线，把指定群的全部新消息收集为上下文；用户 @ 机器人可以简单聊天，讨论中的 bug 和建议整理成反馈。黄煜斯在这台电脑上的同一个测试桌宠里查看原话、反馈并继续追问。

首版只服务这个测试桌宠，不做跨设备同步。完整用户决定、用户故事、边界和验收在 [群反馈 PRD](../tasks/prd-qq-group-feedback.md)。两种长期接入模式仍按 [产品模式与优先级](product-modes.md) 保留，B 站联动仍为可选。

## 推荐实施顺序

### M0：环境与契约就绪

记录插件、宿主、NapCat 和系统版本，验证 QQ 账号可进入指定测试群。确认测试桌宠身份、模型调用和采集说明。宿主开发方提供模式一受控调用契约；如需新增 SDK，同时完成类型仓库、脚手架与宿主契约验证。

可复用旧 DSH 测试作为基线检查，但不能把演示 DSH 私聊视为新群场景已经完成。接口未就绪时，先做协议样本、归属判断和数据模型准备，不绕过宿主边界。

### M1：收消息与查看原文

完成指定群的新消息采集、去重、来源、非文本占位、撤回和断线状态。桌宠能查看收到的记录；这一步先验证采集完整性，不要求每条消息产生模型回复。

### M2：@ 聊天

接入宿主受控模型调用，按当前群上下文回答，并发回原群。验证 @ 自己、@ 他人、@ 全体、自己发送的消息和重复事件；群端不能访问桌面私人聊天。

### M3：反馈整理

从群讨论提取候选 bug 和建议，保存证据和待确认状态。处理进度独立于聊天队列，支持人工纠正、相似反馈关联和失败后重试。

### M4：桌宠查询闭环

提供反馈列表、来源详情和主聊天查询。现场演示：群里报告问题 → 生成待确认反馈 → 测试桌宠展示 → 追问原话与缺失信息。桌面分析不自动发回群。

### M5：真实试点验收与交接

执行 PRD 验收矩阵，加入重启、断网、模型失败、磁盘写入失败和身份切换；旧私聊模式回归与无 B 站场景也要通过。保留脱敏测试记录、启动与故障恢复说明。市场上架和发版另按实际验收结果推进。

## 验证方式

- 协议和业务测试使用合成群事件、模型夹具与固定标注反馈样本，覆盖群归属、来源路由和重复事件。
- 真实 Electron 测试使用隔离 profile、专用 CDP 端口和首帧隐藏，不能占用日常 profile。
- 实际 QQ 测试由接手人使用指定测试账号与测试群执行；记录通过项和未通过项，协议服务器不能代替真实登录收发。
- 涉及 UI 使用 dev-browser 验证完整桌宠中的操作；涉及宿主 SDK 时按宿主插件开发流程补齐契约、类型和脚手架检查。
- 当前命令见 [README](../README.md)；新的群聊与反馈验证命令需随实现提交，不能在交接时声称已有不存在的脚本。

## 交接完成时应留下的材料

1. 实际可运行的提交与兼容版本，模式一和模式二分别标记。
2. 真实测试群的脱敏验收报告、失败项和限制，公开文档不放群号、QQ 号、凭据或聊天原文。
3. 专用电脑的启动、登录失效处理、暂停、恢复、退出、数据备份与清理说明；敏感运行值私下配置。
4. 反馈识别样本、准确率／召回率、处理耗时与模型费用记录。
5. README 的实际能力、市场状态和验证证据；未上架时继续明确写未上架。

原交接轮次仅完成需求准备；后续已开发本地群反馈候选并使用合成协议与隐藏真实应用验证。尚未创建真实 QQ 机器人、运行真实群采集、部署新版本或发送交接通知。
