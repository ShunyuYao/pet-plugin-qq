# QQ 群反馈助手 0.2.0-dev.1：本地候选交付

2026-11-02。用户在了解群反馈 PRD 后要求“帮我制作一下”。本轮沿用既有插件面板风格实现可操作的首版，包含必要的宿主隔离模型选项，不改桌宠主界面、不发布、不部署、不登录真实 QQ。

## 交付效果

指定群的新消息 → 独立加密资料与群上下文 → 真实 @ 原群回复／分批反馈整理 → 面板查看原话、人工修正与确认 → 桌宠主聊天通过只读工具查询反馈和来源。桌面追问不自动发回群；没有 B 站和 DSH 也能走此流程。

这是本地开发候选，不是已经完成真实 QQ 试点、市场上架或真实模型识别质量验收的正式版本。操作说明见 [快速开始](group-feedback-quickstart.md)。

- 插件：`pet-plugin-qq`，基线 `b903d50`，本地分支 `codex/qq-group-collection-m1`；本批是在既有 M1 后端上继续实现。
- 宿主：从 `Test@942cddd1` 的独立 worktree 开发，隔离调用实现提交 `aa450011`；保留 main 独立修复后合并候选为 `893458e4`（源码包显示 0.30.3，不表示已发布包具备新能力）。
- 类型：`pet-plugin-types` 基线 `0f8627ee`；脚手架 `da7543ec`；市场政策 `b537846b`。本地各自保留同步修改，方法数量、apiVersion、包版本与市场条目不变。
- 用户原来较旧、带其他任务未提交成果的宿主检出未被覆盖；自动化使用新建隔离 profile，所有窗口首帧隐藏并通过 CDP 操作。

## 行为与限制

- 群请求只带本群近期最多 16 条消息和最多 3 个带来源批次摘要；每批最多 12 条用于反馈整理。批次摘要与反馈保留来源，撤回／过期时失效；摘要仅作近期辅助，不宣称已把所有历史逐条送入模型。
- 原始非文本消息段可回查，但不下载附件、OCR 或转写。列表截断会标记，完整原消息通过分块接口读取。
- 模型输出必须符合字段与来源白名单；缺失环境字段保持 null。所有新反馈为待确认，不能自动宣称复现、排期或修复。
- 原文入库、反馈进度与发送阶段独立。识别失败保留原文并可重试；重试不重发聊天。提交／发送结果不确定时保留未知状态，不盲目重放。
- 模型次数预算是持久化的保守预留次数，包含失败尝试，不等于付费金额；没有 token usage 不伪造费用数字。模型计费沿用宿主现有路由，未改费率或服务端。
- 隔离群调用不写进主人长期记忆。主人主动查询时，查询结果进入其正常私人聊天，这是用户主动查看；已展示到桌面或已发到群的内容不能自动收回。后续查询以当前证据状态为准。
- 面板编辑不因轮询或定时器自动关闭、覆盖草稿；切换账号／宠物则清除旧作用域的界面与凭据草稿。
- 本地仍为 8 MiB 上限的加密试点快照，原文按操作者选择的期限清理，去重墓碑占容量。长期大流量、磁盘异常实机、系统休眠与多平台仍需试点验收。加密仓的不可解密／损坏返回语义沿用既有宿主，不冒充数据库级灾难恢复。
- 如果主聊天绑定在外部 DSH，主聊天由 DSH 管理，不会调用宿主反馈查询工具；使用群查询前先解除旧绑定，不删除原 DSH 历史。

## 本轮发现与处理

- 开发代理在依赖核查时确认默认后台 AI 会记录经历；以独立隔离入口解决，不用提示词代替记忆／工具隔离，保留真实请求与数据库不变断言。
- 隐藏应用测试发现空筛选条件被编码为 undefined，宿主拒绝；修为省略未选择字段，并保留真实面板 SDK 路径，未放宽宿主校验。
- 合成测试最初把 Harness 的运行状态快照当成最后一条用户问题；检查实际模型请求后修正夹具选择用户消息，不修改生产模型流程以迁就测试。
- CDP 的焦点仿真在单独连接关闭后失效，导致测试“全选”未替换而追加标题；改为同一 CDP 会话中的真实编辑命令与输入，添加输入结果断言，未通过给 DOM 直接赋值绕过。
- 服务边界轮询测试按实际 SDK 限流减频，避免错误条件下每 30ms 请求一次而掩盖原故障。
